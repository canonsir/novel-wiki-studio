# 小说生产工作流

## A. 新书立项

1. 运行 `scripts/new_novel.py`。
2. 填写 `novel.yaml`：类型、读者、体量、视角、基调、禁区。
3. 原稿进入 `raw/manuscript/`。
4. 用导入提示词生成第一版 Wiki。
5. 输出“故事诊断”：卖点、主题、主冲突、人物弧、结构断点、连续性问题、合规风险。
6. 用户确认不可逆决策，写入 `decisions/`。

## B. 原稿导入

- 全文通读 → 按场景切分 → 抽取实体/事件 → 构建时间线 → 建立因果与关系 → 记录伏笔 → 提炼风格 → 生成缺口清单。
- 原文相互矛盾时同时保留，写入 `continuity/contradictions.md`。
- 叙述者说法不等于世界事实；角色台词不等于事实。

## C. 章节重构

1. 明确该章承诺：读者为什么继续读？
2. 列场景卡：目标、阻力、升级、转折、结果、悬念。
3. 检查与前后章的因果连接。
4. 先重构事件，再润色句子。
5. 生成草稿后进行人物声音、细节密度、信息泄露、连续性和合规五轮检查。
6. 采用后同步 Wiki。

## D. 扩写

扩写分四类，必须标注：

- **深化**：同一事件增加动作、感官、潜台词和心理张力。
- **补桥**：补齐因果、时间、空间或情绪跳跃。
- **增戏**：新增场景以完成关系变化或信息变化。
- **开线**：新增人物线/悬念线，风险最高，必须先提案后采用。

默认不以字数为目标，以“有效变化密度”为目标。

## E. Wiki 同步

每次正式采用扩写后：更新场景页、事件页、相关人物状态、时间线、关系变化、伏笔账本、索引与日志。若只产生提案，状态保持 `proposed`。

## F. 视频改编前置

1. 选择章节/事件和目标时长。
2. 把内心信息转为动作、对白、道具、声音或蒙太奇。
3. 生成 beat sheet、分场表和镜头建议。
4. 检查角色/场景资产复用、成本、连续性和可拍性。
5. 输出在 `outputs/video-scripts/`，反向链接场景页。

## G. 发布前闸门

- 剧情与连续性检查通过；
- 公共规则与目标平台 profile 检查通过；
- 版权/隐私/事实核验完成；
- AI 痕迹与低质重复检查完成；
- 用户确认版本号、平台和发布范围。
