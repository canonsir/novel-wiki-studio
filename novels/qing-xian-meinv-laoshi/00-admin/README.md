# 项目管理说明

## 创作目标

将作者本人拥有并授权的原小说进行系统性原创重构，最终形成：

1. 情节完整、章节连续的长篇小说；
2. 人物动机、世界规则和时间线一致的知识库；
3. 可直接拆分为AI短剧的场景、角色和视觉资产；
4. 保留艳遇、势力等级和后台人物三条核心爽点曲线；
5. 不以同义词替换、调序或拼接冒充原创重构。

## 真相状态

- `confirmed`：原稿明确或作者确认；
- `inferred`：依据多个章节合理推导；
- `proposed`：为重构新增，尚未进入正式正文；
- `contradicted`：来源互相冲突；
- `deprecated`：已被新版本替代。

补写章节在正式采用前属于 `proposed`。V2对标点和错字的确定性修复不改变剧情状态。

## 文件职责

- `raw`：原始来源，只读；
- `wiki`：权威事实与创作规则；
- 编号目录：面向作者和短剧生产的中文阅读视图；
- `drafts`：小说正文与重构草稿；
- `outputs`：短剧脚本和对外交付；
- `reports`：导入、校对和剧情审查报告；
- `decisions`：作者确认的重要决定。

## 完成标准

一批章节只有同时满足以下条件才算完成：

1. 正文已重写或校订；
2. 人物状态已同步；
3. 时间线和伤势已同步；
4. 新地点、势力和道具已登记；
5. 伏笔投放与回收已更新；
6. 短剧场景卡已生成；
7. 错别字、标点、段落和标题检查通过；
8. 未解决剧情问题已列入台账。

## 版本说明

### V1 连续性重构基线

保留授权原稿主体，补齐缺章并统一747章编号。用途是保证完整阅读和后续逐批替换。

### V2 全文校订版

在V1基础上：

- 清理平台求票、加更和节日祝语；
- 统一中文标点与引号；
- 修复高置信度错别字；
- 每个小说段落使用Markdown空行分隔；
- 拆分过长段落；
- 保留剧情级问题供后续重构。

V2不是最终原创重写版，不能把自动校对当作剧情重构完成。
