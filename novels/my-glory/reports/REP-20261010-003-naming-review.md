> 本报告按 **工程硬约束 + 真实世界撞名风险 + 读者辨识度** 三条标准做评估。所有建议在用户 ACK 之前**不动任何现有页面**。

## 硬约束回顾（为何需要评审）

1. 国家红线 checklist §48："真实机构 / 公司 / 品牌出现敏感情节必须虚构化。"
2. 红果 AI 短剧 checklist §49："不使用真实品牌 / 商标。"
3. 番茄 + 红果封面图：不含真人肖像 / 真实品牌 / 真实地标。
4. KB README 第 10 行："真实机构 / 品牌 / 法律：虚构化具体名称或模糊化到行业。"
5. **本作世界观：虚实结合**——保留文化根脉（袍哥 / 洪门 / 淮军），但具体组织名应与真实历史组织**可区分**。

## 二、Soul / 嗖匹配 评估

### 原稿背景

- 原稿用微信漂流瓶→现代读者看不懂 → 飞书设定 §5.4 把它换成 "Soul 虚化为嗖匹配"。
- 开篇场景（匿名约见 → 校花老师仙人跳 → 师生错位 → 情感勒索）属于典型"敏感情节"。

### 可否恢复 Soul？

**结论：不能恢复为 "Soul"。** 原因三条：

1. **国家红线 §48** 明确："真实机构 / 公司 / 品牌出现敏感情节必须虚构化"——本作开篇是全书最大的敏感情节（陌生约见 + 女性安全 + 高富帅勒索），直接用 Soul 名字就是把真实 App **放到负面叙事里**，侵权 + 诱发品牌投诉双风险。
2. **红果 §49**："不使用真实品牌 / 商标"——短剧改编 100% 过不了。
3. **番茄发布**：虽然小说正文审核相对宽松，但当代都市文一旦涉及真实约会 App 名字的仙人跳叙事，被下架或要求修改是常态（头部网文平台历史案例多见）。

### "嗖匹配" 现在的问题

你说得对：**"嗖匹配" 像是刻意英译中的拼音转换**（Soul→嗖），读者一眼就能看穿，反而**暴露了对真实品牌的参照**。这在国家红线下和"虚构化"要求里也是一种**不彻底的虚构**。

### 推荐（二选一，不恢复 Soul）

| 推荐 | 名字 | 理由 |
|---|---|---|
| **A** | **「漂流」** | 直接命名 App 为"漂流"——漂流瓶机制是本作开篇的核心交互，App 以机制命名，读者立刻懂；没有任何真实 App 撞名；像一个独立的虚构小众 App |
| **B** | **「有缘」** | 匿名社交常用意象；中文自然；没有真实 App 撞名；强调"随机命中"的宿命感，呼应本作命理主轴 |

**我的推荐**：**A（「漂流」）**。理由：

- 一词即功能，自然；读者在"下载了漂流""扔了个漂流瓶出去"中都读得通
- 匿名社交平台名字本身应该是**反品牌感的**（真实的 Soul / Tinder / Blued 名字都偏抽象）；"漂流"刚好符合这种**反品牌气质**
- 短剧改编时字幕上一个"漂流 App"图标，审核没有争议

**次推荐**：B「有缘」——如果你想要更东方味。

### 其他可选（若 A/B 都不喜欢）

- 「随缘」 / 「随遇」 / 「拾光」 / 「拾梦」 / 「微澜」 / 「浪记」
