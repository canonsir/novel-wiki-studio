# 文件命名规则候选

## 问题

当前目录大量使用拼音/英文 ID（`char-chen-haonan.md`、`evt-anonymous-date.md`、`scn-s1-c001-main.md`），用户 review 时无法从文件名直接判断是谁或什么事件。

## 候选规则（三选一或自定义）

### 方案 A｜中文名并列（推荐）
保留 ASCII ID 文件 + 新增中文符号链接或副本，二者等价。
- 优点：工程脚本/图谱/双链继续工作，review 友好。
- 缺点：维护两套文件名；需要 lint 脚本保证一一对应。

示例：`char-chen-haonan.md` ↔ `人物-陈浩南.md`（符号链接或 Git LFS 外副本）

### 方案 B｜中文作为主文件名（彻底切换）
`characters/陈浩南.md`、`events/匿名约见.md`、`scenes/S1第01章-匹配.md`。
- 优点：review 最直观。
- 缺点：
  - 需要重写 `scripts/lint_wiki.py`、`scripts/build_story_graph.py`、`scripts/rebuild_index.py` 的解析逻辑；
  - 图谱 `story-graph.json` 中 240 个节点 ID、7822 条边都要同步重写；
  - Obsidian 双链 `[[characters/char-chen-haonan|陈浩南]]` 要全量重写；
  - Git 历史 rename 识别可能失败。

### 方案 C｜中文前缀 + 保留 ID（我推荐）
文件名改为 `陈浩南__char-chen-haonan.md` 格式——中文名在前，review 一眼看到；ID 保留在后，脚本/图谱/双链无需任何修改。
- 优点：
  - 不改脚本：所有 lint/graph 脚本按 glob 读文件，不解析文件名；
  - ID 仍可唯一检索；
  - 双链语法 `[[characters/陈浩南__char-chen-haonan|陈浩南]]` 直接可用。
- 缺点：文件名略长；需要在创建新文件时统一规则。

### 方案 D｜最小改动（我的次选）
不改文件名，只改 `wiki/characters/_index.md`、`wiki/scenes/_index.md` 等分类索引，使其按"中文名 | 文件 ID | 状态"三列展示；review 入口全部从 _index.md 走，不直接读 `char-*.md` 文件名。
- 优点：零迁移成本、零风险。
- 缺点：review 时如果直接浏览目录仍只看到英文。

## 命名规则正式提案（无论采用哪种方案都需遵守）

### 字符
- 文件名只能用中文、英文字母、数字、下划线 `_`、短横 `-`、句点 `.`；禁止空格、特殊符号。
- 中文使用小说官方正名；别名/旧名放 frontmatter `aliases: [...]`，不出现在文件名。

### 分类与前缀
- 人物：`人物-<中文名>.md` 或 `人物-<中文名>__<ID>.md`
- 地点：`地点-<中文名>.md`
- 事件：`事件-<中文名>.md`
- 场景：`场景-S1-C01-<中文标题>.md`
- 组织/帮派：`帮派-<中文名>.md`
- 伏笔：`伏笔-<中文名>.md`
- 道具：`道具-<中文名>.md`
- 关系：`关系-<双方>.md`
- 术语：`术语-<中文名>.md`
- 决策：`决策-<日期>-<简述>.md`
- 章节草稿：`章节-S<卷>-C<章号三位>-<中文标题>.md`
- 报告：`报告-<类型>-<日期>-<简述>.md`

### 冲突处理
- 同名人物（如"张建国 vs 李建国"）：加职业/身份后缀，`人物-张建国_建国哥.md`。
- 迁移文件：新文件创建后，旧文件 `status: deprecated`，加 `replaced_by:` 并保留历史记录直到用户确认删除。

### 排序
- 卷/章文件按 `S<卷号>-C<三位章号>-<中文标题>` 排序，保证按文件名字母序即章序。
- 场景卡 `scn-s1-c001-main.md` → `场景-S1-C01-01-匹配.md`，支持多场景拆分 `S1-C01-01`、`S1-C01-02`。

## 迁移成本评估

| 方案 | 迁移工作量 | 脚本改动 | 图谱改动 | 风险 |
|---|---|---|---|---|
| A 中文符号链接 | 中（~250 文件新建副本）| 需要 lint 规则 | 无 | 维护成本 |
| B 彻底切换 | 高（~250 文件重命名+Git+脚本+图谱）| 大改 | 全量重建 | 高 |
| C 中文前缀双段式 | 中（~250 文件改名）| 无 | 无 | 低 |
| D 只改索引 | 低（改 ~10 个 _index.md）| 无 | 无 | 极低 |

## 推荐

**先用方案 D 立刻缓解 review 不便（成本极低）**；在用户确认后，再评估是否升级到方案 C（彻底好 review 且脚本不改）。方案 B 不建议——会把工程稳定性拖进高风险区。
